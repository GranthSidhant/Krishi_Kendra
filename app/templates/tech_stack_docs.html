1. Database Layer: Relational PostgreSQL / SQLite + SQLAlchemy ORM

How data integrity, financial escrow safety, and relational entities are modeled.

RDBMS Architecture
What is a Relational Database (RDBMS)?

A Relational Database organizes data into structured tables consisting of rows and columns with strict mathematical schemas. Tables are connected to one another through Primary Keys (Unique IDs) and Foreign Keys (Relationships).

Key Principles Used in Krishi Kendra:
  • ACID Guarantees: Atomicity, Consistency, Isolation, Durability ensure Escrow funds cannot be debited without an exact matching credit.
  • Relational Integrity: An Order cannot exist without a valid User (Farmer), User (Buyer), and Inventory.
  • Foreign Key Cascades: Protects against orphaned records or inconsistent transaction states.
Relational (SQL) vs Non-Relational (NoSQL) — Why SQL?
Feature Relational (PostgreSQL/SQLite) - Ours Non-Relational (MongoDB / NoSQL)
Data Structure Structured Tables, Rigid Schemas, Strict Types Unstructured JSON-like BSON Documents
Relationships Foreign Keys & Joins (User.id == Order.farmer_id) Embedded docs or unvalidated references
Financial Safety ACID Compliant (Crucial for Escrow transactions) BASE / Eventual Consistency (Risk of race conditions)
Why We Chose SQL Agriculture marketplaces handle financial Escrow orders, user authentication, and government IDs. Financial integrity requires strict ACID compliance over loose document storage.
What is SQLAlchemy ORM?
SQLAlchemy Official Docs

ORM (Object-Relational Mapping) is a software design pattern that lets developers query and manipulate database tables using Python object-oriented classes instead of writing raw SQL strings like SELECT * FROM users WHERE id=1.

# Example from our codebase (app/models.py):
class Order(db.Model):
  id = db.Column(db.Integer, primary_key=True)
  farmer_id = db.Column(db.Integer, db.ForeignKey('users.id'), nullable=False)
  escrow_status = db.Column(db.String(30), default='funded')

# Querying in Python without raw SQL:
order = Order.query.filter_by(farmer_id=current_user.id).first()

2. Backend Layer: Python 3.14 + Flask 3.0 Micro-Framework

Application routing, Blueprints, modular services, session security, and REST endpoints.

Application Architecture
What is Flask & Application Factory Pattern?

Flask is a lightweight Python WSGI micro-framework created for rapid, clean API and web development. Unlike monolithic frameworks, Flask gives fine-grained control over middleware, routing, and database sessions.

Modular Architecture (Flask Blueprints):
  • auth_bp: Login, registration, role selection, profile avatars.
  • farmer_bp: Crop inventory, AI Crop Doctor, profit calculator.
  • buyer_bp: Produce browsing, requirement posting, direct offer bidding.
  • chat_bp: Real-time negotiation chat, counter-offers, quote binding.
  • api_bp: AI voice assistant queries, Mandi forecasting, user popups.
Security & Cryptography

Enterprise-grade safeguards built directly into request lifecycles:

  • Password Hashing: Werkzeug's generate_password_hash() using pbkdf2:sha256 with cryptographic salt. Passwords are never stored in plaintext.
  • Session State & JWT: Secure HTTP-only cookies and tokenized authorization headers prevent session hijacking.
  • Privacy Protection: Phone numbers are masked across the platform unless the user explicitly grants consent in profile privacy settings.

3. Frontend Layer: Vanilla CSS3, Semantic HTML5 & Modern JavaScript

High-performance, lightweight UI engine designed for 2G/3G connectivity in rural India.

Zero-Bloat UI
What is Vanilla CSS & Why Did We Use It?

Vanilla CSS means writing native Cascading Style Sheets without relying on heavy external utility frameworks (such as Tailwind CSS, Sass compilers, or runtime CSS-in-JS).

Why Vanilla CSS is Crucial for Farmers:
  • Sub-Second Page Loads: Zero JavaScript build overhead or unused utility bloat. The entire CSS bundle is under 30KB.
  • CSS Custom Properties (Design Tokens): We defined a unified color palette (--primary, --success, --k-surface) ensuring consistency across all 15+ pages.
  • Responsive Glassmorphism & Micro-animations: Rich modern aesthetics with smooth hardware-accelerated CSS transforms.
Native Vanilla JavaScript (ES6+) Features

All client-side interactions run on native browser APIs without heavy React/Angular bundles:

  • Fetch API: Asynchronous background HTTP requests for real-time AI voice queries and negotiation counter-offers.
  • Web Speech API: Native SpeechRecognition (voice-to-text) and SpeechSynthesis (multilingual text-to-speech audio readout).
  • Chart.js: Lightweight HTML5 Canvas rendering for 7-day Mandi price trajectories and comparative profit bars.

1. Mandi Price Trajectory & Storage ROI Model

Engineered in app/services/price_forecast_service.py:

  • Momentum Trajectory: Ingests daily APMC modal rates ($P_{\text{modal}}$) and calculates 7-day projections using directional drift factors ($\mu = +1.8\%$ for upward, $-1.5\%$ for downward, $+0.8\%$ for stable).
  • Confidence Interval Formula:
    P_min = P_modal * (1.0 - Volatility)
    P_max = P_modal * (1.0 + Volatility)
  • Cold Storage ROI Optimization Formula:
    Gross Gain = P_projected_10d - P_current
    Storage Cost = Daily Rental Rate * 10 Days
    Net Gain = Gross Gain - Storage Cost
  • Decision Trigger: If Net Gain ≥ 5% and crop has storage potential → 🟢 "HOLD & STORE"; else → 🟠 "SELL NOW".

6. Round 3 Jury Cross-Questions & Scripted Answers

Core technical cross-questions asked in hackathons with high-scoring, precise answers.

Pitch Defense
Q1 "What database are you using and why not a NoSQL database like MongoDB?"

Answer: "We use a Relational Database (PostgreSQL / SQLite via SQLAlchemy ORM). An agricultural marketplace handles financial Escrow transactions, buyer-farmer trade quotes, and order statuses. These workflows require strict ACID compliance (Atomicity, Consistency, Isolation, Durability) to ensure that funds cannot be deducted without an exact corresponding delivery milestone. In NoSQL databases, eventual consistency creates risk of double-spending or orphaned records during multi-party negotiations."

Q2 "What is an ORM and what benefits does SQLAlchemy provide?"

Answer: "An ORM (Object-Relational Mapping) abstracts relational database tables into native Python classes. SQLAlchemy provides three major benefits: (1) Security: Automatically prevents SQL Injection attacks via parameterized queries; (2) Portability: Lets us run SQLite locally for testing and seamlessly switch to PostgreSQL in production without altering code; and (3) Maintainability: Enables clean relational joins between Users, Inventory, and Escrow Orders using Python methods."

Q3 "Why did you choose Vanilla CSS instead of Tailwind or Bootstrap?"

Answer: "In rural India, farmers frequently access our platform over slow 2G/3G connections. Heavy CSS frameworks bundle hundreds of kilobytes of unused classes and runtime dependencies. By using Vanilla CSS with CSS Custom Properties (Design Tokens), we achieved a sub-30KB stylesheet that loads in under 1 second, while maintaining custom glassmorphism, responsive cards, and vibrant micro-animations."

Q4 "How does your AI Crop Doctor work under the hood?"

Answer: "The Crop Doctor utilizes Google Gemini 2.5 Flash's multimodal vision model. When a farmer uploads an image, the raw bytes are transmitted with a system prompt instructing the vision model to identify visual pathology patterns (e.g., target-board necrotic spots of Early Blight vs water-soaked lesions of Late Blight). The model returns structured JSON with confidence percentages, organic biological remedies (like Neem oil), and chemical fungicides with exact dosages."

Q5 "How do you ensure transaction security in the closed-loop trade chain?"

Answer: "We enforce a 4-state Escrow machine: (1) Funded: Buyer deposits funds before truck dispatch; (2) In Transit: Driver enters Pickup OTP at farm gate; (3) Delivered: Buyer enters Delivery OTP upon arrival; (4) Released: Funds instantly disburse to the farmer's bank account. This eliminates default risk for farmers and non-delivery risk for buyers."

Q6 "How does your Mandi Price Prediction and Forecasting Model work?"

Answer: "Our Price Forecasting Service (price_forecast_service.py) implements a time-series momentum and volatility-weighted trajectory algorithm. It ingests live daily APMC modal rates, calculates directional momentum vectors, and applies commodity-specific volatility indexes (e.g. 5.5% for perishable Tomatoes vs 1.2% for dry Wheat). It outputs a 7-day projected price band with min, modal, and max confidence intervals to help farmers time their harvest sales for peak profit."

Q7 "How does the platform predict whether a farmer should hold produce in Cold Storage?"

Answer: "The engine calculates a Net Storage Financial ROI: it projects 10-day price appreciation and subtracts cumulative cold storage rental fees (₹0.45 to ₹1.20/day/Qtl). If the projected net gain exceeds cumulative storage fees by ≥ 5%, the system advises 'HOLD & STORE' showing the exact extra rupees per quintal. If market trends are downward or stagnant, it recommends immediate sale to prevent spoilage and storage cost drag."
